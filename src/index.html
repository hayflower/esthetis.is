Esthetis

Independent infrastructure and security consulting for small teams.

Blaise Bellew · Ventura County, CA · Remote · Revised 2026-11-01

Who

I'm Blaise Bellew. Esthetis is my consulting practice. I set up, secure and look after the infrastructure small teams run on, and I document it so they aren't dependent on me.

Most of my clients so far have been small teams running blockchain infrastructure: nodes, RPC endpoints, key management. In practice that is ordinary Linux operations with an unforgiving threat model. Uptime, monitoring, patching, backups and secrets handling all matter more when a mistake can't be undone. The same work applies to any small team that wants to own its infrastructure.

There's one person here. You deal with me directly, from the first message to handover.

What

covers
Linux server deployment and hardening. Monitoring and alerting. Backups, with recovery tested rather than assumed. Migrating off hosted and cloud providers to self-managed servers. Access and secrets management. Node and RPC hosting for teams that need it.

Running systems, runbooks for operating them, and an architecture document you can hand to whoever comes after me.

security/

I review your code and your infrastructure and tell you what's wrong with it. Threat model first, so the review is about your actual adversary and not a checklist.

Web application review. Server and deployment configuration. Dependencies and supply chain. Key and secret handling. Operational security for small teams: MFA, device management, least-privilege access.

Selected work

Client names and identifying details are withheld under NDA.

Migrations and handovers

A payments startup ran its production system on AWS. Working alongside their two developers, I migrated it to self-managed servers. Hosting costs came down by roughly half, and the team took over the new setup with backups in place and documentation for running it.

On another engagement I took over systems that had been built and run without documentation, worked out what they did and how they fit together, and left the client with runbooks and architecture documents for all of it.

MFA and device management for an eight-person team

An eight-person team needed MFA and managed devices. I rolled out MFA through Entra ID, enrolled their devices in Intune and moved shared credentials into Bitwarden. The team ended up with MFA in place and shared passwords kept in one managed vault.

Silent fallback in key generation

During a security review, I traced the client's key generation path and found that keys created in production were not coming from a cryptographically secure source. The entropy module tested for a secure random API once, at load time, and if it was missing fell back without warning to the runtime's general-purpose generator. A refactor had moved the import of the shim that provides that API below the entropy module, so in affected builds the check always ran first and every key took the fallback.

That generator isn't built for cryptography and its internal state can be recovered from its output, so every key from those builds had to be treated as guessable. I recommended removing the fallback so key generation fails closed, adding a startup self-test and a build-time check on import order, and forcing rotation of affected keys, with affected users contacted directly before any public statement. The client implemented the fixes.

Notes

PHP2Shell response, October 2026

PHP released fixes for CVE-2026-109618 and CVE-2026-109619 ("PHP2Shell"), two remote code execution flaws in PHP itself, on 21 October 2026. Exploitation attempts were being reported the same day. I started work about nine hours after disclosure on a client site running an affected PHP 8.3 release under PHP-FPM.

I put up a maintenance page, upgraded to PHP 8.3.36, restarted services and restored the site. I also disabled session upload progress, as PHP recommends until the related CVE-2026-115560 is fixed in its next regular release, and tightened the request body limit at the web server.

To verify the fix, I confirmed the running version from both the CLI and FPM, checked that the package changelog listed both CVEs, confirmed the new setting was active, and tested login, booking and checkout end to end.

To check for compromise, I reviewed web and PHP logs back to the first reported in-the-wild attempts. A small number of oversized multipart requests appeared in the days around disclosure. All were rejected or failed, and none were followed by unusual activity from the same sources. CMS core and plugin checksums were clean, no PHP files had been added or changed in the web root, and crontabs, admin accounts and outbound connections showed nothing unusual. No signs of compromise were found.

Total downtime was about 15 minutes. No action was required from the client.

Process

  1. Mail

    Tell me what you're running and what you need. A paragraph is enough to start.

  2. Call

    Thirty minutes, no charge. We work out whether I'm the right person for it. Sometimes I'm not, and I'll tell you so and point you at someone better.

  3. Scope

    I write down what I'll do and what it costs, with a date attached. You approve that before any work starts, and if the scope changes later it changes in writing.

  4. Work

    Progress arrives in writing as it happens. No standing status meetings unless you want them.

  5. Handover

    Everything documented, in files you keep. I stay reachable afterwards for questions about what I built.

Terms

rates
On request. You get a fixed price with the written scope, before anything starts.

Fixed scope and fixed price where the work can honestly be scoped. Day rate where it genuinely can't, with a cap agreed up front. I don't bill retainers for months I'm not working.

How I handle access and data

I ask for as little access as the work needs, and I give it back when the work is done.

accounts
Scoped to the job and short-lived, read-only where read-only is enough. I won't ask for a password that outlives the work.
your data
Stays on your systems wherever possible. Anything I need a copy of is kept only for the length of the engagement.
handover
Findings and documentation go to a repository you control. Copies on my side are destroyed, and I confirm when that's done.

Fit

Worth mailing about

  • You want to run your own infrastructure and need help getting there.
  • Something is live and you want it reviewed before more people depend on it.
  • Your team needs accounts, MFA and devices set up properly.
  • You inherited a system nobody documented and need to know what it does.

Not for me

  • Work that needs me to take custody of your credentials or funds.
  • Anything that would require me to be dishonest.
